# Settings, connected devices and optional biometric sign-in

Settings keeps four categories: Connection & devices, Controls, Appearance, and Privacy & security. Each settings card opens from its heading. Search opens matching cards. Cards mounted before category setup, including Connected devices and App updates, are moved into their appropriate category. Original controls and event handlers are retained, including capability-based visibility. The text/link send box and its buttons are removed from Connected devices; automatic clipboard sync and the Files interface remain.

Other connected phones/browsers have Rename and Remove actions. Removal requires an inline confirmation, persists across host restarts, removes that device's targeted inbox deliveries and revokes its saved sessions and live access within the same account. The current device and Windows host cannot remove themselves through this action. A removed device can join again after a new password sign-in. Existing PC files are not deleted.

Android 2.3.5 provides optional local biometric protection for an existing remembered sign-in, using AndroidX Biometric 1.1.0 and an origin-bound Android Keystore AES-GCM proof requiring strong biometrics for each use. Native host-session verification is required before changing biometric settings. Cancellation, failed crypto and stale callbacks cannot authorize a screen. Password fallback clears the remembered session before loading ordinary sign-in. The app does not receive fingerprint/face templates or store the PC password. Protected sessions do not automatically appear in a mini-window when leaving the app. File picker workflows and native background transfers remain usable.

Biometric unlock does not renew expired host sessions or add server TOTP. It does not encrypt every WebView cookie or claim bank approval. Android manages the sensor and its lockout; hardware with weaker face recognition must use a strong fingerprint or ordinary password sign-in.

Validation: 27 focused checks passed across expandable Settings, late-mounted controls, account-scoped removal, persistent session revocation, biometric controls, sync, folder sync, companion preferences and update UI. The earlier combined interface/transport check passed 87 tests. Android unit checks cover origin binding, stale results and replay. Physical Android biometric success/cancel/lockout, app resume, install-over and system-bar layout still need a device check.
